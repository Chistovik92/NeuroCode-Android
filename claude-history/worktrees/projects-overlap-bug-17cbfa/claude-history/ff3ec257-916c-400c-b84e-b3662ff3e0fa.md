## Что сейчас блокирует iOS

Проект на 100% нативный Android, и часть стека завязана на платформу без прямых аналогов:

| Компонент | Android | Проблема для iOS |
|---|---|---|
| UI | Jetpack Compose | Portable через Compose Multiplatform, но с доработкой под iOS-паттерны |
| Локальный inference | llama.cpp через JNI, ABI-сборки (arm64/armv7/x86_64) | У llama.cpp есть официальный iOS-порт (Metal), но биндинг нужно переписывать отдельно от JNI |
| Терминал/агент-окружение | proot + Alpine Linux, произвольные shell-команды | **Главный блокер.** iOS-сэндбокс не даёт запускать произвольные процессы и chroot-подобные среды — Linux-userland в духе proot там невозможен в принципе (это не вопрос трудозатрат, а ограничение платформы) |
| Git | JGit (JVM) | Нет JVM на iOS — нужен libgit2/ObjectiveGit или KMP-обёртка |
| Редактор кода | Sora Editor (Android View) | Android-only библиотека — на iOS нужен другой движок (Runestone, TextKit-based, либо WebView + CodeMirror/Monaco) |
| Хранение ключей | Android Keystore | Аналог есть — iOS Keychain |
| Импорт/экспорт проектов | SAF (Storage Access Framework) | Аналог — UIDocumentPicker/Files app, логика переписывается заново |

## Варианты

1. **Kotlin Multiplatform (KMP) + общее ядро** — вынести в `commonMain` чисто логическую часть: сетевые клиенты к провайдерам, парсинг стрима/reasoning, модели данных, tool-loop агента (без exec), хранение диалогов/проектов. UI можно оставить нативным (Compose/SwiftUI) либо тоже общим через Compose Multiplatform. Реалистичный путь, раз Compose уже выбран.
2. **Отдельное нативное iOS-приложение (Swift)** без переиспользования кода — дольше и дороже, но не тянет компромиссов платформы.
3. **Flutter/React Native с нуля** — не имеет смысла, учитывая уже вложенные JNI/llama.cpp/proot-интеграции на Android.

## Рекомендация и главный компромисс

KMP-ядро + нативный UI на каждой платформе — самый прагматичный путь, но agent-функциональность на iOS не будет 1:1: **произвольный shell/proot-терминал придётся либо сильно урезать (ограниченный набор команд без реального Linux), либо перенести часть агентного цикла на удалённый бэкенд** (agent выполняет команды не локально на телефоне, а через сервер/SSH).
