## 🎯 Планируемые версии

### 🟦 **NeuroCode Android 0.8.0** — Инфраструктура (Фаза 0)
**Статус:** Разработка  
**Срок:** 2-3 недели (неделя 0-1)  
**Приоритет:** 🔴 КРИТИЧНО — базис для всех следующих версий

#### Доступ к файловой системе Android
- **Filesystem Manager** — поиск файлов по всей FS, а не только в разрешённой папке
  - Поддержка Android Storage Access Framework (SAF) для работы с Uri
  - Поиск файлов по названию, расширению, размеру
  - Кэширование разрешённых URI
  - Интеграция в AgentOrchestrator для доступа агента к полной FS

- **UI экран разрешений** — управление доступом к файлам
  - Список предоставленных разрешений
  - Возможность отозвать доступ
  - Запрос разрешений при необходимости

#### Изоляция диалогов и проектов через UUID
- **Dialog Manager** — уникальные идентификаторы для каждого диалога
  - Структура хранения с UUID вместо названия
  - Уникальность даже при одинаковых названиях
  - Метаданные: дата создания, последнего обновления, теги, пины
  
- **Модель DialogMetadata**
  ```kotlin
  data class DialogMetadata(
    val id: String,              // UUID
    val name: String,            // Отображаемое название
    val type: DialogType,        // CHAT, REQUEST, PROJECT
    val createdAt: Long,
    val updatedAt: Long,
    val tags: List<String>,
    val isPinned: Boolean
  )
  ```

- **Миграция данных** — перевод существующих диалогов на UUID базис
  - Автоматическая миграция при запуске
  - Сохранение полной истории диалогов

**Технические изменения:**
- `FilesystemManager.kt` — новый компонент для работы с FS
- `DialogManager.kt` — управление диалогами с UUID
- `PathGuard.kt` — расширение для работы с Uri
- `ChatRepository.kt` — адаптация под UUID
- `ProjectRepository.kt` — адаптация под UUID

## 🔄 Процесс разработки для каждой версии

### Pre-Release
1. Создать ветку: `git checkout -b feature/v{version}-{name}`
2. Реализовать функции согласно плану
3. Написать unit/integration тесты
4. Запустить CI: `./gradlew test detekt build`

### Release
1. Обновить `VERSION` файл
2. Обновить `versionCode` в `build.gradle.kts`
3. Обновить `release_notes.txt` с описанием версии
4. Создать pull request в `main` ветку
5. После merge создать Git tag: `git tag v{version}`
6. Собрать APK: `./gradlew bundleRelease`

### Post-Release
1. Опубликовать на GitHub Releases
2. Обновить ROADMAP.md
3. Создать issues для следующей версии
