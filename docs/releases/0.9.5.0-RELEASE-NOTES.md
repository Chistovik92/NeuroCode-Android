# 0.9.5.0 — аккаунт и синхронизация между устройствами

versionCode 43 · раздел ROADMAP: «0.9.5» · план: `docs/PLAN-0.9.5.md`

## Новое

- **Аккаунт (вход Google/GitHub).** Настройки → Аккаунт: вход через OAuth PKCE
  (Custom Tab, редирект `neurocode://oauth`), состояние сессии, выход и удаление
  данных аккаунта. Refresh-токен — в Android Keystore (`CredentialKey.Account`);
  анонимный режим остаётся полноправным, синхронизация — опция.
- **Синхронизация между устройствами (Supabase).** Диалоги (журнал 0.8.5), проекты,
  скиллы, пресеты, конфигурация провайдеров и выбор модели переносятся между
  устройствами. Бэкенд — таблица `sync_blobs` в Supabase (PostgREST, RLS по
  `auth.uid()`), вход — Google или GitHub. URL проекта и anon-ключ вводятся
  в «Аккаунт → Настройки синхронизации».
- **E2E-шифрование.** Payload шифруется на устройстве AES-256-GCM ключом
  синхронизации (32 случайных байта); сервер видит только шифртекст. Ключ
  генерируется на первом устройстве и показывается фразой (base64url группами
  по 4 символа), на втором устройстве вводится в «Аккаунт». API-ключи и токены
  не синхронизируются никогда (Keystore не покидает устройство).
- **Модель как ссылка.** Локальная GGUF переносится как `ModelRef` (имя + id),
  файл — нет: на втором устройстве модель предлагается к скачиванию из каталога
  (0.9.1) или импорту; подпись модели у сообщений сохраняется даже если модель
  на устройстве недоступна.
- **Правила мержа.** Last-writer-wins по времени изменения (при равенстве —
  детерминированный tie-break по deviceId), удаление — tombstone: удалённое на
  одном устройстве удаляется и на другом и не «воскресает».
- **Режимы запуска.** «Синхронизировать сейчас», автосинк при старте приложения,
  переключатель «только по Wi-Fi» (в мобильной сети синк пропускается без ошибки).

## Инфраструктура

- `sync/`: `SyncCrypto` (AES-256-GCM конверт `sync-envelope-v1`), `SyncModels`
  (`SyncPayload`/`SyncSettings` без секретов), `SyncMerge` (LWW + tombstones),
  `SupabaseAuthClient` (GoTrue REST поверх OkHttp, PKCE RFC 7636),
  `AccountRepository` (OAuth Custom Tab + refresh в Keystore), `SyncRepository`
  (сборка payload, PostgREST upsert/fetch, применение remote-изменений).
- Тесты: `SyncCryptoTest`, `SyncMergeTest`, `SyncPayloadTest`,
  `SupabaseAuthClientTest` (212 тестов зелёные); detekt-baseline обновлён.
- `MainActivity`: обработка deep link `neurocode://oauth` (onCreate + onNewIntent);
  `AppContainer`: `credentials`, `account`, `sync`.

## Настройка синхронизации (один раз)

1. Создать проект на supabase.com; Authentication → Providers: Google
   (OAuth-клиент в Google Cloud с redirect `https://<ref>.supabase.co/auth/v1/callback`)
   и GitHub (OAuth App с тем же callback);
2. Authentication → URL Configuration → Redirect URLs: `neurocode://oauth`;
3. SQL-редактор:
   ```sql
   create table sync_blobs (
     user_id uuid not null,
     device_id text not null,
     device_name text,
     payload text not null,
     updated_at timestamptz not null default now(),
     primary key (user_id, device_id)
   );
   alter table sync_blobs enable row level security;
   create policy "own blobs" on sync_blobs
     for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
   ```
4. В приложении: Настройки → Аккаунт → URL и anon-ключ → «Войти через Google/GitHub»
   → «Показать ключ» на первом устройстве → «Ввести с другого устройства» на втором
   → включить синхронизацию.

## Ограничения первой версии

- Не синхронизируются: API-ключи и токены, содержимое рабочих папок и SAF-корней,
  spill-файлы (в сообщении остаётся inline-префикс), настройки самой синхронизации.
- При сильном расхождении настроек действует LWW целиком (выбор при конфликте — 0.9.5.x).
- Ключ синхронизации при утере восстанавливается только генерацией нового и
  полной выгрузкой заново (серверные данные перезаписываются).
- Фоновый WorkManager-синк по расписанию — вместе с 0.10.6.

## Проверено

- Компиляция debug/release, 212 unit-тестов, detekt (baseline обновлён).
- На устройстве не проверялось: вход с реальным Supabase-проектом и перенос
  между двумя устройствами — требуется настройка проекта (см. выше).
