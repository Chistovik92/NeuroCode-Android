# NeuroCode Android 0.8.5 Release Notes

**Дата релиза:** 5 ноября 2026
**Версия:** 0.8.5 (versionCode 32)
**Тема:** Ядро сессий из DeepSeek Harness

## Что нового

В 0.8.5 впервые встроено «ядро сессий» — инфраструктура хранения, поиска,
сжатия контекста и выноса крупных результатов инструментов за пределы журнала
(«spill»), спроектированная по архитектуре DeepSeek Harness (пакеты `session`,
`session-query`, `storage`, `compaction`, `context`, `spill`, `attachment`).

### Журнал сессий (JSONL)

Каждая реплика и результат инструмента дописываются в append-only журнал сессии
(`state/session-events/<id>.jsonl`) как версионированное событие `SessionEvent`
(тип, роль, id сообщения, имя инструмента, модель, содержимое, метка времени).
Формат несёт номер версии и готов к миграциям. API-ключи и секреты в журнал
не попадают.

### Поиск по сессиям (`ChatRepository.search`)

Поиск по тексту (название и сообщения), проекту, имени инструмента и ключу
модели — без учёта регистра.

### Сжатие контекста (`SessionContextBuilder.compact`)

Функция `compact()` сворачивает старые ходы истории в сводку (системное
сообщение), сохраняя исходный журнал. Автозапуск по приближению к окну
модели запланирован на 0.8.6/0.9.2.

### Spill (`SpillStore`)

Большие результаты инструментов (вывод команд, чтение файлов) больше не
раздувают контекст: они сохраняются в `.neurocode/spill`, а в контекст
попадают начало и ссылка — модель может дочитать кусок по запросу.

### Сборка контекста (`SessionContextBuilder.build`)

Единая точка сборки контекста диалога через `HistoryAdapter` с учётом
возможностей модели (`TargetCapabilities`), подключена в `AgentOrchestrator`.

### Индикатор `fs_*` в чате

Вызовы инструментов файловой системы сохраняют имя разрешённого корня
(`ChatMessage.fsRootName`); в чате показывается чип «📁 Использована папка»
или «🔍 Поиск», включая историю после перезапуска.

### Fallback-маркер proot

Для устройств, где Linux-окружение недоступно (SIGSYS на Android 15,
`noexec` на `filesDir`), выставляется маркер `.android-shell-fallback` и
корректно описывается причина сбоя (`describeExit`).
