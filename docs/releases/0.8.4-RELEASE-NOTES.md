# NeuroCode Android 0.8.4 Release Notes

**Дата релиза:** 4 ноября 2026  
**Версия:** 0.8.4 (versionCode 31)  
**Тема:** Session Core — Event-Based Architecture

## Что нового

### Архитектура сессий из DeepSeek Harness

Версия 0.8.4 внедряет фундаментальное изменение в хранении и обработке диалогов: переход от списка сообщений к **журналу событий** (event log). Это основа для всех будущих улучшений работы агента.

#### 1. Event-Based Session Format (v2)

**Старый формат (v1):**
```
.neurocode/session/{sessionId}/chat.json
├── messages: List<ChatMessage>
```

**Новый формат (v2):**
```
.neurocode/session/{sessionId}/
├── metadata.json          (SessionMetadata)
├── events.jsonl          (журнал событий, JSON Lines)
└── spill/               (большие результаты)
    └── {eventId}.txt
```

**Типы событий:**
- `UserMessageEvent` — сообщение пользователя
- `AssistantMessageEvent` — ответ модели
- `ToolCallEvent` — вызов инструмента
- `ToolResultEvent` — результат инструмента
- `ModelSwitchEvent` — смена модели
- `ContextCompactedEvent` — сжатие контекста

#### 2. Spill Manager — вынос больших результатов

Когда инструмент возвращает больше 8000 символов (~2000 токенов), результат:
1. Сохраняется в `.neurocode/spill/{sessionId}/{eventId}.txt`
2. В контекст попадает только превью (500 символов)
3. Агент может дочитать полный результат через ссылку

**Преимущества:**
- Экономия токенов контекста
- Защита от переполнения окна модели
- Возможность работать с очень большими файлами

**Политика spill:**
```kotlin
SPILL_THRESHOLD_CHARS = 8000
SPILL_PREVIEW_CHARS = 500
```

#### 3. Context Compaction — автоматическое сжатие

Когда диалог приближается к лимиту окна модели (80% заполнения):
1. Старые события автоматически компактируются в сводку
2. Генерируется `ContextCompactedEvent` с резюме
3. Исходные события удаляются из активного контекста
4. Освобождённое место используется для новых сообщений

**Политика сжатия:**
```kotlin
COMPACTION_THRESHOLD_PERCENT = 80   // когда начинать
COMPACTION_TARGET_PERCENT = 50      // до какого уровня сжать
MIN_EVENTS_BEFORE_COMPACTION = 20   // минимум событий
```

**Пример сводки:**
```
=== Compacted context summary ===
Period: 2026-11-04 10:00:00 to 2026-11-04 11:30:00

UserMessageEvent: 15 events
AssistantMessageEvent: 15 events
ToolCallEvent: 23 events
ToolResultEvent: 23 events

User messages:
  - Create a new React component for user profile...
  - Fix the authentication bug in login...
  - Add unit tests for the API client...
  ... and 12 more

Tools used:
  - write_file: 8 times
  - read_file: 10 times
  - shell: 5 times

Assistant responses: 15
=== End of summary ===
```

#### 4. Context Builder — сборка с бюджетом токенов

Новый слой `ContextBuilder` собирает контекст для запроса с учётом бюджета:

```kotlin
data class TokenBudget(
    val total: Int,           // всего доступно
    val system: Int,          // системный промпт
    val skills: Int,          // скиллы
    val project: Int,         // контекст проекта
    val history: Int,         // история диалога
    val attachments: Int,     // вложения
    val reserved: Int = 1024  // резерв
)
```

**Преимущества:**
- Точный контроль расхода токенов
- Предсказуемое поведение на границе лимита
- Возможность предпросмотра контекста (для будущего UI)

#### 5. Session Query — поиск по событиям

Мощный поиск по всем событиям сессии:

```kotlin
SessionQuery(
    sessionId = "abc123",
    eventType = ToolCallEvent::class,     // только вызовы инструментов
    textSearch = "authentication",        // поиск по тексту
    modelId = "gpt-4",                   // только эта модель
    toolName = "write_file",             // только этот инструмент
    fromTimestamp = ...,                 // временной диапазон
    toTimestamp = ...,
    limit = 100
)
```

**Применение:**
- Отладка: найти все вызовы конкретного инструмента
- Аналитика: сколько раз модель обращалась к файлам
- Восстановление: найти момент, когда появилась ошибка

#### 6. Автоматическая миграция v1 → v2

При первом открытии проекта после обновления:
1. Проверяется версия формата в `metadata.json`
2. Если `version == 1`, происходит конвертация:
   - `ChatMessage` → `SessionEvent`
   - Tool calls распаковываются в отдельные события
   - Смены моделей становятся `ModelSwitchEvent`
3. Сохраняется в новом формате с `version = 2`
4. Старый `chat.json` сохраняется как резервная копия

**Обратная совместимость:**
- UI продолжает работать без изменений
- Адаптер `EventsToMessagesAdapter` преобразует события обратно в сообщения для отображения

## Для разработчиков

### Работа с новым форматом

```kotlin
// Создание события
val event = UserMessageEvent(
    sessionId = session.id,
    content = "Hello, agent!",
    attachments = emptyList()
)

// Сохранение
storage.append(event)

// Загрузка сессии
val events = storage.loadSession(sessionId)

// Поиск
val toolCalls = storage.query(
    SessionQuery(
        sessionId = sessionId,
        eventType = ToolCallEvent::class
    )
)
```

### Проверка на spill

```kotlin
val result = executeCommand("cat very_large_file.log")

val finalResult = if (spillManager.shouldSpill(result)) {
    val ref = spillManager.spill(sessionId, eventId, result)
    ToolResultEvent(
        sessionId = sessionId,
        callId = callId,
        result = spillManager.getPreview(result),
        spillRef = ref
    )
} else {
    ToolResultEvent(
        sessionId = sessionId,
        callId = callId,
        result = result
    )
}
```

### Сборка контекста

```kotlin
val contextBuilder = StandardContextBuilder(spillManager)

val result = contextBuilder.build(
    sessionId = session.id,
    events = events,
    maxTokens = 4096,
    systemPrompt = systemPrompt,
    includeSpilled = false
)

// result.messages готовы для отправки модели
// result.budget показывает расход токенов
// result.spilledResults содержит ссылки на spill
```

## Миграция существующих проектов

**Автоматически:** при первом открытии проекта после обновления

**Вручную:**
```kotlin
val migration = SessionMigration
val (metadata, events) = migration.convertSession(oldSession)

storage.updateMetadata(metadata)
events.forEach { storage.append(it) }
```

## Известные ограничения

1. **UI интеграция** — UI пока работает через адаптер, полная интеграция в будущих версиях
2. **Compaction алгоритм** — текущая версия использует простую текстовую сводку, LLM-based summarization будет добавлена позже
3. **Поиск** — индексация in-memory, персистентная индексация в будущих версиях
4. **Cleanup** — автоматическая очистка старых spill-файлов пока не реализована
