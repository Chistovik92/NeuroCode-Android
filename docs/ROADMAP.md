# Дорожная карта NeuroCode Android

Статусы: ✅ готово · 🚧 в работе · ⬜ запланировано

## Логика версий

- `0.x.0` — завершённый этап дорожной карты;
- `0.x.N` — последовательные улучшения и исправления внутри этапа;
- версии всегда растут: `0.1 → … → 0.7 → 0.8 → 0.9 → 0.10 → 1.0`;
- текущая версия: **0.7.5** (versionCode 23); ближайший выпуск: **0.7.6**,
  следующие этапы: **0.8 → 0.9 → 0.10**, затем стабильный **1.0**.

## Известные проблемы 0.7.5

Найдены при проверке на устройстве (скриншоты настроек и выбора модели) и по коду.
Исправления идут в `0.7.6`, подробности — в разделе ниже.

| Проблема | Причина (по коду) | Версия |
|----------|-------------------|--------|
| Linux-окружение не устанавливается, в настройках только «недоступно на этом устройстве» | `libproot.so` в APK не входит, а proot скачивается в `filesDir`; при `targetSdk 36` Android запрещает запускать такие файлы (SELinux). Ошибка скрыта: `ProotManager.initialize()` делает `runCatching{…}.getOrDefault(false)` и причину не показывает | 0.7.6 |
| Кнопка «Сбросить Linux-окружение» сжата в узкий столбец | `Row` с двумя кнопками без `weight`/переноса | 0.7.6 |
| Окно «Выбор модели» оформлено по-старому в новом дизайне | `ModelSwitcherDialog` (`ChatScreen.kt`) использует цвета и скругления классического дизайна, строка текущей модели переносится по символам рядом с «Обновить», чипы провайдеров обрезаются, список без группировки и пометок | 0.7.6 |
| Скиллы не проверены на практике | только ручное тестирование; нет unit-тестов на `AgentSkill`/`systemPrompt`/импорт | 0.9.2 |
| Нет автоматической загрузки GGUF: модель можно только импортировать из файла | не реализовано | 0.9.1 |
| Нет коннекторов (MCP) и плагинов | не реализованы | 0.10 |
| Модель видит только файлы проекта | `PathGuard.resolveWithin` ограничивает любой путь корнем проекта; в манифесте только `INTERNET` | 0.8.1 |

### 0.7.1 — изоляция проектов и дизайны по референсам

**Изоляция проектов.** Диалоги, терминал и синхронизация больше не переносят данные
одного проекта в другой.

- [x] диалоги привязаны к проекту: список чатов фильтруется по активному проекту,
  при переключении выбирается последний диалог этого проекта, а агент получает
  проект **из самой сессии**, а не из текущего выбора — история старого проекта
  больше не применяется к файлам нового (это и была причина «наложения» проектов);
- [x] разовая миграция: диалоги без привязки к проекту получают текущий проект,
  чтобы история не пропала после обновления;
- [x] одна папка синхронизации не может быть привязана к двум проектам — при попытке
  показывается предупреждение с именем проекта-владельца;
- [x] терминал перезапускается в корне выбранного проекта (в том числе после
  фоновой установки proot) и очищает буфер вывода при переключении.

**Дизайны по референсам.** Оба варианта оформления доведены до HTML-макетов.

- [x] классический дизайн (GitHub-dark) подогнан под референс: разделители под
  верхней панелью и над нижней навигацией, бейдж модели с полупрозрачной заливкой
  и рамкой акцентного цвета, нижняя навигация без «таблетки» Material 3

### 0.8.0 — изоляция диалогов, запросов и проектов

Что уже есть: проекты лежат в `files/workspaces/<UUID>` (имя проекта не влияет на путь),
у диалога и сообщения есть UUID, диалог привязан к `projectId`, вложения — в
`.neurocode/attachments` своего проекта, папка синхронизации — одна на проект (0.7.1).
Остаётся то, из-за чего данные можно «слить в кучу»:

- [ ] проекты и диалоги с одинаковым или похожим названием различимы в интерфейсе:
  короткий идентификатор (4–6 символов UUID) в списках, при создании — предупреждение о
  совпадении имени и предложение «создать отдельный»;
- [ ] хранение диалогов: вместо одного `state/chats.json` — `state/chats/<UUID>.json` на диалог
  плюс лёгкий индекс (id, заголовок, `projectId`, даты); запись одного диалога не переписывает
  остальные, повреждение файла не затрагивает соседние;
- [ ] одиночные запросы без проекта получают собственную песочницу
  `files/workspaces/<UUID>` и не используют чужой проект как рабочую папку;
- [ ] копирование и клонирование диалога создаёт новый UUID и не делит вложения со старым;
- [ ] миграция `chats.json` → отдельные файлы при первом запуске с резервной копией;
- [ ] unit-тесты: два проекта и два диалога с одинаковыми названиями, перенос файлов между

### 0.9.1 — автоматическая загрузка подходящих GGUF с Hugging Face

Цель: пользователь не ищет файл вручную — приложение само предлагает модели с
[huggingface.co](https://huggingface.co/), которые потянет именно этот телефон, и скачивает выбранную.

- [ ] **Подбор под устройство.** Из `DeviceProfile` берутся ОЗУ, число ядер, архитектура и
  `maxModelSizeMb`; рекомендация считается с запасом под контекст и систему (на 32-битных и
  low-RAM устройствах — только компактные модели). Предлагаются только файлы, чей размер не
  превышает рекомендованный, остальные скрыты или помечены «слишком большая»;
- [ ] **Каталог моделей.** Поиск через публичный API Hugging Face (`/api/models` с фильтром `gguf`,
  сортировка по популярности/свежести, поиск по названию), список файлов репозитория
  (`/api/models/<repo>/tree/main`); группировка по семействам (Qwen, Llama, Gemma, Phi, …) и
  выбор квантизации: по умолчанию наибольшая из `Q4_K_M` → `Q5_K_M` → `Q8_0` и т.д., что помещается
  в рекомендованный размер; показываются размер, квантизация, лицензия, instruct/base;
- [ ] **Раздел «Рекомендовано для этого телефона»** в «Моделях на устройстве» с кнопкой
  «Скачать» в один тап и ручной поиск рядом;
- [ ] **Загрузка.** Файл забирается по `/<repo>/resolve/main/<file>` с поддержкой `Range`
  (докачка после обрыва), сверка SHA-256 с данными LFS из API, проверка magic header GGUF, затем
  перенос в `files/models`; проверка свободного места до начала, опция «только по Wi‑Fi»,
  отмена и очистка недокачанного;
- [ ] **Закрытые (gated) модели:** необязательный токен Hugging Face, хранится в Keystore как
  остальные секреты; без токена такие модели не предлагаются;
- [ ] после загрузки модель становится активной (или предлагается переключиться), проверяется
  предупреждением о размере, как и при ручном импорте;
- [ ] только HTTPS, список и скачивание не отправляют на сервер данных о диалогах; характеристики
  устройства для подбора считаются локально и не передаются;
- [ ] unit-тесты: выбор квантизации под разные профили устройства, разбор ответа API, докачка и
  проверка хэша на тестовом сервере.

- [ ] манифест `plugin.json` (имя, версия, автор, описание) + набор из скиллов, внешних инструментов

- [ ] плагины работают через те же `ApprovalGate` и ограничения, что и ручные настройки.

## На рассмотрении (не запланировано)

Идеи, требующие отдельного архитектурного решения до включения в дорожную карту.

- **Удалённый режим клиента (iOS-путь).** Сейчас NeuroCode — полностью локальное
  приложение (proot/Linux-терминал, JGit, offline GGUF-inference на устройстве),
  что делает честный порт на iOS дорогим: у Linux-терминала, JGit и Sora Editor
  нет прямых аналогов в песочнице iOS. Альтернатива, которую использует
  [OpenCode Мобильный](https://play.google.com/store/apps/details?id=com.logicedge.opencodemobile)
  (неофициальный клиент к OpenCode Server) — тонкий клиент, который подключается
  по HTTP/HTTPS (LAN или Tailscale/VPN) к агенту, выполняющемуся на ПК/сервере,
  без локального выполнения кода на телефоне. Такой режим был бы дополнением
  к текущему локальному (не заменой) и переносится на iOS через общее ядро
  (KMP: сетевой клиент, парсинг стрима, модели данных) значительно дешевле, чем
  локальный агентный цикл. Требует отдельного решения: серверный компонент
  NeuroCode для ПК плюс протокол подключения (аутентификация, обнаружение,
  переподключение).
