# NeuroCode Android 0.8.4 — Session Core Implementation Plan

**Дата начала:** 4 ноября 2026  
**Версия:** 0.8.4 (versionCode 31)  
**Тема:** Ядро сессий из DeepSeek Harness

## Цель

Внедрить архитектуру сессий из DeepSeek Harness как фундамент для всех будущих улучшений работы агента: события вместо сообщений, автоматическое сжатие контекста, spill для больших результатов, отдельный слой сборки контекста с бюджетом токенов.

## Источник

DeepSeek Harness пакеты:
- `session` — журнал событий сессии
- `session-query` — поиск по событиям
- `storage` — хранение и миграции
- `compaction` — автоматическое сжатие контекста
- `context` — сборка контекста с бюджетом
- `spill` — вынос больших результатов
- `attachment` — работа с вложениями

## Требования из ROADMAP.md

- [ ] формат сессии как журнал событий (сообщение, вызов инструмента, результат, смена модели) с версией формата и миграциями
- [ ] поиск по сессиям: по тексту, проекту, модели, инструменту, дате
- [ ] автоматическое сжатие контекста: когда история подходит к окну модели, старые ходы сворачиваются в сводку
- [ ] «spill»: большие результаты инструментов → `.neurocode/spill`, в контекст попадает начало + ссылка
- [ ] сборка контекста как отдельный слой: системный промпт, скиллы, проект, вложения — с бюджетом токенов

## Архитектурное решение

### 1. Формат событий (Session Event Log)

```kotlin
// Базовое событие
sealed interface SessionEvent {
    val id: String
    val timestamp: Long
    val sessionId: String
}

// Типы событий
data class UserMessageEvent(
    override val id: String,
    override val timestamp: Long,
    override val sessionId: String,
    val content: String,
    val attachments: List<AttachmentRef> = emptyList()
) : SessionEvent

data class AssistantMessageEvent(
    override val id: String,
    override val timestamp: Long,
    override val sessionId: String,
    val content: String,
    val modelId: String,
    val reasoning: String? = null
) : SessionEvent

data class ToolCallEvent(
    override val id: String,
    override val timestamp: Long,
    override val sessionId: String,
    val toolName: String,
    val arguments: JsonObject,
    val callId: String
) : SessionEvent

data class ToolResultEvent(
    override val id: String,
    override val timestamp: Long,
    override val sessionId: String,
    val callId: String,
    val result: String,
    val spillRef: String? = null,  // reference to .neurocode/spill/{id}
    val success: Boolean = true,
    val error: String? = null
) : SessionEvent

data class ModelSwitchEvent(
    override val id: String,
    override val timestamp: Long,
    override val sessionId: String,
    val fromModelId: String?,
    val toModelId: String,
    val reason: String? = null
) : SessionEvent

data class ContextCompactedEvent(
    override val id: String,
    override val timestamp: Long,
    override val sessionId: String,
    val compactedCount: Int,
    val summary: String,
    val tokensFreed: Int
) : SessionEvent
```

## Миграция из текущей архитектуры

### Текущее состояние (0.8.3)

- `ChatSession` содержит `messages: List<ChatMessage>`
- Каждое `ChatMessage` — это `UserMessage` или `AssistantMessage`
- Tool calls хранятся внутри `AssistantMessage.toolCalls`
- Файл диалога: `.neurocode/session/{sessionId}/chat.json`

### Целевое состояние (0.8.4)

- `ChatSession` содержит `events: List<SessionEvent>`
- События хранятся в `.neurocode/session/{sessionId}/events.jsonl` (JSON Lines)
- Большие результаты инструментов → `.neurocode/spill/{sessionId}/{eventId}`
- Сжатые участки → `ContextCompactedEvent` в событиях

### Стратегия миграции

1. **Формат версионирования**
   ```kotlin
   data class SessionMetadata(
       val version: Int,  // текущая: 2
       val createdAt: Long,
       val lastEventId: String?,
       val compactionCount: Int = 0
   )
   ```

2. **Конвертация при загрузке**
   - Если `metadata.version == 1`, читаем `chat.json` (старый формат)
   - Конвертируем `ChatMessage` → `SessionEvent`
   - Сохраняем в `events.jsonl` (новый формат)
   - Обновляем `metadata.version = 2`

3. **Обратная совместимость**
   - UI продолжает работать с абстракцией `ChatViewModel`
   - Адаптер `EventsToMessagesAdapter` собирает события в сообщения для UI
   - Tool calls восстанавливаются из пар `ToolCallEvent` + `ToolResultEvent`
