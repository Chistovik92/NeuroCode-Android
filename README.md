# NeuroCode Android

[![Android build](https://github.com/Chistovik92/NeuroCode-Android/actions/workflows/android.yml/badge.svg)](https://github.com/Chistovik92/NeuroCode-Android/actions/workflows/android.yml)

NeuroCode — автономная среда для работы с AI-кодинг-агентом прямо на Android, без обязательного ПК или сервера. Проект вдохновлён рабочим процессом OpenCode, но не связан с командой OpenCode.

## Что уже реализовано

- чат с несколькими OpenAI-compatible API-провайдерами;
- готовые профили OpenAI, OpenRouter, DeepSeek, Groq, Google Gemini и Mistral;
- выпадающий список моделей из API провайдера (в том числе для своих агрегаторов);
- автоматический краткий контекст проекта в агентном режиме (пути и размеры файлов без содержимого);
- собственные HTTPS endpoint и идентификатор модели;
- агентный цикл с инструментами list_files, read_file, write_file, replace_in_file, delete_file, search_text, run_command, git_status и git_diff;
- потоковый вывод токенов облачных и локальных моделей (SSE + llama.cpp);
- сохранение действий агента в историю диалога;
- подтверждение записи файлов и опасных shell-команд;
- проекты во внутренней песочнице приложения;
- диалоги привязаны к проекту: в списке чатов видны только диалоги активного
  проекта, при переключении открывается его последний диалог, а агент работает
  с проектом самой сессии — история одного проекта не попадает в файлы другого;
- создание проекта и импорт папки через Storage Access Framework;
- экспорт проекта обратно в любую папку устройства через Storage Access Framework;
- экспорт всего проекта одним ZIP-архивом;
- двусторонняя синхронизация с внешней папкой (привязка папки, туда и обратно);
  одна папка привязывается только к одному проекту, чтобы файлы не смешивались;
- светлые и тёмные темы с переключением; интерфейс адаптируется под экран
  (нижняя панель на телефоне, боковая панель на планшетах и в landscape);
- выбор дизайна интерфейса в настройках: стандартный (GitHub-dark) или новый
  Material 3 Expressive с палитрой в стиле Gemini, крупными радиусами и
  градиентными акцентами (подробнее — раздел «Дизайны интерфейса»);
- новая адаптивная иконка приложения с монохромным слоем для themed icons;
- редактор Sora Editor с номерами строк, undo/redo, поиском и языковой подсветкой
  (Kotlin, Java, Python, JS/TS, C/C++, Go, Rust, Shell, SQL, YAML/TOML/JSON,
  XML/HTML, CSS, Markdown);
- LSP-клиент: диагностики языкового сервера для открытого файла (команда сервера настраивается);
- встроенный Android shell-терминал;
- опциональное Linux-окружение на proot + Alpine для терминала и команд агента
  (установка в один тап из настроек, workspace доступен как /workspace);
- Git через JGit: init, status, diff, stage, commit, история и HTTPS remote — clone, pull, push;
- подписанный release-APK в CI (секреты) и локально через keystore.properties;
- импорт GGUF и реальный локальный inference через официальный Android binding llama.cpp;
- потоковый вывод токенов локальной модели;
- поддержка 32-битных ARMv7 процессоров: отдельный APK `armeabi-v7a` с нативной сборкой;
- профиль устройства в настройках: архитектура CPU, ядра, ОЗУ и рекомендованный
  размер GGUF-модели (0.5B–7B+ Q4); предупреждение при импорте слишком большой модели;
  на слабых устройствах автоматически сокращается бюджет генерации локальной модели;
- шифрование API-ключей через Android Keystore;
- резервная копия файла перед каждой перезаписью;
- автоматическая сборка debug APK в GitHub Actions.

## Дизайны интерфейса

Дизайн переключается в «Настройки → Оформление» и меняет не только палитру, но и
навигацию. Оба варианта поддерживают режимы System / Light / Dark.

**Стандартный (GitHub-dark)** — плотный рабочий интерфейс: верхняя панель с именем
проекта и монохромным бейджем активной модели, нижняя навигация из пяти вкладок
(Чат, Код, Терминал, Git, Настройки), разделители между панелями, акцент — зелёный
(#3FB950) без «таблетки» Material 3 под выбранной вкладкой. В чате сообщение
пользователя — сплошной зелёный пузырь, ответ агента — панель с рамкой. Терминал
чёрный с зелёным приглашением `$`, diff в цветах GitHub.

**Новый (Material 3 Expressive / Gemini)** — интерфейс вокруг диалога: шапка с
градиентным брендом, кнопкой нового диалога, выбором модели и проекта, меню
инструментов разработчика (Диалог / Код / Терминал / Git) и шестерёнкой; нижней
навигации нет, настройки открываются полноэкранной шторкой. Пустой диалог
встречает градиентным приветствием, ответы модели идут без подложки с
градиентным аватаром, поле ввода — «таблетка» с круглой кнопкой отправки.
Терминал и Git используют тёмную dev-палитру (#0D0E0F), приглашение `❯`,
карточки коммитов с хеш-чипом и пилюлей ветки.

## Системные требования

- Android 13 или новее (minSdk 33);
- основные целевые архитектуры — **arm64-v8a** и **arm-v7** (32-битные ARMv7);
- для локальных моделей желательно 6–12 ГБ RAM;
- свободное место: размер GGUF-модели плюс минимум 256 МБ;
- Android Studio с JDK 17;
- Android SDK 36, NDK 29.0.13113456, CMake 3.31.6.

## Терминал и Linux-окружение

По умолчанию терминал запускает /system/bin/sh под обычным UID приложения. Root не нужен и не используется. Доступны только команды, которые поставляются самим Android.

В разделе «Настройки → Среда выполнения» можно установить Linux-окружение: приложение скачает статический proot (репозиторий Alpine `proot-static`) и мини-образ Alpine Linux, распакует их во внутреннее хранилище и запустит интерактивный shell и команды агента внутри user-space Linux. Проект монтируется как `/workspace`, PATH включает стандартные каталоги `/usr/bin`. Если загрузка не удалась или устройство не позволяет исполнять загруженные бинарники, NeuroCode автоматически возвращается к Android shell. Установленное окружение можно сбросить в настройках.

Сессия терминала принадлежит выбранному проекту: при переключении проекта shell
перезапускается в его корне, а буфер вывода очищается, чтобы команды и логи не
смешивались между проектами.

Git-функции интерфейса работают отдельно через JGit и не зависят от окружения терминала.

## Сборка в Android Studio

1. Откройте корень проекта NeuroCode-Android.
2. Дождитесь Gradle Sync.
3. Android Studio предложит установить SDK/NDK/CMake из build-файлов.
4. Выберите конфигурацию app.
5. Запустите Run или Build → Build APK(s).

Командная сборка:

~~~bash
./scripts/build-debug.sh
~~~

Готовый APK:

~~~text
dist/NeuroCode-arm64-v8a-debug.apk
~~~

Скрипт делает отдельный APK для обычных arm64-телефонов, удаляет отладочные
символы из нативных библиотек, выравнивает и повторно подписывает его стандартным
debug-ключом. Вариант для эмулятора остаётся в
`app/build/outputs/apk/debug/app-x86_64-debug.apk`.

## Автоматическая сборка APK

После загрузки проекта в GitHub откройте:

~~~text
Actions → Android build → Run workflow
~~~

Артефакт neurocode-debug-apk будет доступен в завершённом запуске workflow.

## Release-подпись

Debug-вариант подписан стандартным debug-ключом. Для подписанного release-APK:

1. Создайте собственный ключ (храните вне репозитория):

   ~~~bash
   keytool -genkeypair -v -keystore neurocode-release.jks \
     -alias neurocode -keyalg RSA -keysize 4096 -validity 10000
   ~~~

2. Локальная сборка — создайте `keystore.properties` в корне (в .gitignore):

   ~~~text
   storeFile=/абсолютный/путь/neurocode-release.jks
   storePassword=пароль_хранилища
   keyAlias=neurocode
   keyPassword=пароль_ключа
   ~~~

   и выполните `./gradlew :app:assembleRelease`.

3. GitHub Actions — добавьте четыре секрета (Settings → Secrets and variables → Actions):
   `RELEASE_KEYSTORE_BASE64` (base64 файла .jks), `RELEASE_STORE_PASSWORD`,
   `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`. После push workflow соберёт артефакт
   neurocode-release-apk. Без секретов шаг подписи автоматически пропускается.

base64 файла: Linux/macOS `base64 -w0 neurocode-release.jks`, Windows
`certutil -encode neurocode-release.jks encoded.txt` (содержимое между BEGIN/END).

## Первый запуск

1. Создайте новый проект или импортируйте папку.
2. Откройте «Настройки».
3. Выберите API-провайдера, нажмите редактирование и введите API-ключ.
4. Вернитесь в «Чат» и опишите задачу.
5. Подтверждайте только те изменения и команды, которые понятны.

Для локального режима:

1. В «Настройки» нажмите «Импортировать GGUF».
2. Выберите квантованную instruct-модель.
3. После копирования включится локальный режим.

В версии 0.1 локальная модель работает как чат-помощник и автоматически получает
контекст открытого файла. Инструменты агента (`write_file`, `run_command`, Git и
другие) пока вызываются только моделями через совместимый облачный API. При этом
сами команды и изменения всегда выполняются локально на Android, а не на сервере
NeuroCode.

Для телефонов разумная отправная точка:

- 0.5–1.5B Q4 — 3–4 ГБ RAM;
- 2–3B Q4 — 6–8 ГБ RAM;
- 7B Q4 — обычно 10–12+ ГБ RAM и заметный нагрев.

Модель в архив не включена.

## Безопасность

- API-ключи и токены Git remote хранятся отдельно от JSON-настроек и шифруются AES-GCM ключом из Android Keystore.
- HTTP endpoint запрещены: поддерживается только HTTPS.
- Агент не получает инструмент чтения произвольных путей.
- Все пути канонизируются и обязаны оставаться внутри активного проекта.
- Диалог агента привязан к своему проекту: контекст и правки одного проекта не
  переносятся в другой, а одна папка синхронизации принадлежит одному проекту.
- Рекурсивное удаление, системные команды и curl | sh помечаются как опасные.
- Перед перезаписью файл копируется в .neurocode/history/.
- Папка .neurocode добавляется в стандартный Git ignore.
